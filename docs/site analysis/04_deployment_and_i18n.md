# Deployment and Internationalization (i18n)

## Vercel Deployment Setup
The project is hosted and built on Vercel.
- **Build Command**: `nuxt build` (defined in `package.json` under `build`).
- **Output Directory**: Vercel utilizes the `.vercel/output` standard generated by Nitro (Nuxt's underlying server engine).
- **Environment**: Node environment, using standard Nuxt 3 deployments.

## Internationalization (i18n) Configuration
The site uses `@nuxtjs/i18n` to support two languages: **English (en)** and **Bulgarian (bg)**.

### Configuration (`nuxt.config.ts`)
```javascript
i18n: {
  locales: [
    { code: 'en', iso: 'en-US', file: 'en.json', name: 'English' },
    { code: 'bg', iso: 'bg-BG', file: 'bg.json', name: 'Български' }
  ],
  defaultLocale: 'en',
  lazy: true,
  strategy: 'prefix_except_default', 
  detectBrowserLanguage: {
    useCookie: true,
    cookieKey: 'i18n_redirected',
    redirectOn: 'root',
  }
}
```

### Routing Strategy
- **`prefix_except_default`**: This means English pages will be accessible at the root path (e.g., `/portfolio`), while Bulgarian pages will be prefixed with `/bg` (e.g., `/bg/portfolio`).

### Dictionary Files
- The translation strings are stored in JSON format.
- While `nuxt.config.ts` refers to `en.json` and `bg.json` (likely located in an `i18n/locales/` or `app/locales/` directory), there are also files named `en_new.json` and `bg_new.json` in the root, which seem to be used for active translations or bulk synchronization scripts (`merge_locales.py`, `check_i18n.py`).
- **Usage**: When adding new static text to a Vue template, it MUST be wrapped in the `$t('key')` helper instead of hardcoding text to ensure it supports the active locale switch.

### Switching Locales
In `app/layouts/default.vue`, the locale switch uses Nuxt i18n's `switchLocalePath()` helper:
`<NuxtLink :to="switchLocalePath('bg')">🇧🇬 &nbsp; Български</NuxtLink>`
